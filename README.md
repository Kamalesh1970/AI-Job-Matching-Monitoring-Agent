# AI Job-Matching & Monitoring Agent (Phase 1, Phase 2, Phase 3 & Phase 4)

A reliable, modular job ingestion, deduplication, resume-to-job matching, Telegram digest, and scheduled monitoring daemon designed for an AI & Data Science candidate seeking relevant Machine Learning, Data Science, and Software Development positions.

> **Disclaimer**: The match score generated by this system is a **ranking signal**, NOT a probability of hiring or interview success.  
> **Notice**: *The Telegram integration sends job recommendations for human review. It does not automatically apply to jobs.*  
> **Operational Note**: *A healthy scheduler process does not necessarily mean the job pipeline is healthy. Health is determined from recent successful pipeline completion.*

---

## 1. Project Purpose & System Pipeline

The long-term pipeline of the AI Job-Matching & Monitoring Agent encompasses:
1. **Source Fetchers** (Phase 1 - Adzuna API)
2. **Dedup & SQLite Storage** (Phase 1 - Exact & Fingerprint deduplication)
3. **Resume & Job Matching Engine** (Phase 2 - Semantic embeddings, Skill extraction, Rule filtering)
4. **Telegram Daily Job Digest** (Phase 3 - Threshold filtering, Notification deduplication, Telegram delivery)
5. **Scheduler & Reliability Infrastructure** (Phase 4 - APScheduler daemon, Heartbeat monitoring, Stale health alerts, Failure isolation)

---

## 2. Phase Scope & Architecture

### Phase 1: Ingestion & Deduplication
- Fetches jobs via Adzuna API with search keywords.
- Normalizes titles, locations, descriptions, and salary currency.
- Generates SHA-256 content fingerprints for deduplication in SQLite (`data/jobs.db`).

### Phase 2: Resume & Job Matching Engine
- **Semantic Embeddings**: Uses `all-MiniLM-L6-v2` via `sentence-transformers` for cosine similarity calculation.
- **Skill Overlap**: Regex boundary matching against canonical tech skills.
- **Rule Filtering**: Evaluates experience level (filtering senior/lead roles) and location preferences.
- **Weighted Match Score (0 - 100)**: 50% Semantic + 30% Skill + 20% Rule compatibility.

### Phase 3: Telegram Daily Job Digest
- **Decoupled Notification Service**: `TelegramNotifier` handles HTTPS requests to the official Telegram Bot API (`sendMessage`).
- **Minimum Score Threshold**: Notifies only matches meeting or exceeding `TELEGRAM_MIN_MATCH_SCORE` (default 70.0).
- **Message Formatting & Chunking**: Formats clean job cards and chunks messages under character limits while strictly preserving job card boundaries.
- **Notification Deduplication & Failure Resilience**: Tracks sent notifications in SQLite (`job_notifications` table). Records notifications **only after** delivery confirmation.

### Phase 4: Scheduler, Reliability & Heartbeat Monitoring
- **APScheduler Daemon**: `PipelineScheduler` runs periodic monitoring cycles using background interval triggers.
- **Overlap & Misfire Protection**: Configured with `max_instances=1`, `coalesce=True`, and `misfire_grace_time=900` to prevent duplicate concurrent runs.
- **Failure Isolation**: Component failures (Adzuna network errors, missing resume, or Telegram HTTP errors) are caught, logged, and isolated. No single error terminates the scheduler daemon process.
- **Pipeline Run Tracking**: Every execution is recorded in SQLite (`pipeline_runs` table) with status (`SUCCESS`, `PARTIAL_FAILURE`, `FAILED`), metrics, duration, and error details.
- **Heartbeat & Health Evaluation**:
  - `HEALTHY`: Last successful run completed within `HEARTBEAT_TIMEOUT_MINUTES`.
  - `STALE`: Time since last successful run exceeds `HEARTBEAT_TIMEOUT_MINUTES`.
  - `FAILED`: Last run suffered a critical failure.
- **Deduplicated Health Alerts**: Dispatches a Telegram operational alert upon transitioning into a `STALE` state, recorded in `health_alerts` to prevent notification spam. Automatically resolves active alerts when a run succeeds.
- **Graceful Shutdown**: Listens for `SIGINT` and `SIGTERM` signals to cleanly stop the scheduler daemon without interrupting active DB transactions.

## 5. Running the Application

### Scheduled Monitoring Daemon (Phase 4 Scheduler Mode)
Runs APScheduler as a long-running background service daemon:
```bash
python3 -m app.main --scheduler
```

### Single Execution Run (Manual / Cron Mode)
Executes one complete monitoring pipeline cycle (Ingestion -> Matching -> Digest -> Health check) and exits:
```bash
python3 -m app.main --run-once
```

### Phase 3 Telegram Digest Mode
```bash
python3 -m app.main --digest
```
