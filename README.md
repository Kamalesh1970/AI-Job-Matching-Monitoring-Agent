# AI Job-Matching & Monitoring Agent (Phases 1, 2, 3, 4, 5 & 6)

A reliable, modular job ingestion, deduplication, resume-to-job matching, Telegram digest, scheduled monitoring daemon, multi-source Yellow-tier ingestion engine, and Gmail API email alert ingestion system designed for an AI & Data Science candidate seeking relevant Machine Learning, Data Science, and Software Development positions.

> **Disclaimer**: The match score generated by this system is a **ranking signal**, NOT a probability of hiring or interview success.  
> **Notice**: *The Telegram integration sends job recommendations for human review. It does not automatically apply to jobs.*  
> **Operational Note**: *A healthy scheduler process does not necessarily mean the job pipeline is healthy. Health is determined from recent successful pipeline completion.*
> **Responsible Use Note**: *"Internshala integration is designed for conservative personal-scale monitoring and does not attempt to bypass anti-bot protections."*
> **Security & Privacy Note**: *"Gmail API access strictly uses the read-only OAuth scope (`https://www.googleapis.com/auth/gmail.readonly`). The system NEVER sends, modifies, deletes, moves, or marks emails as read. Credentials and tokens are git-ignored and stored locally."*

---

## 1. Project Purpose & System Pipeline

The long-term pipeline of the AI Job-Matching & Monitoring Agent encompasses:
1. **Source Fetchers** (Phase 1 - Adzuna API, Phase 5 - Internshala Yellow-tier source, Phase 6 - Gmail API LinkedIn & Indeed alert ingestion)
2. **Dedup & SQLite Storage** (Phases 1, 5 & 6 - Exact & Fingerprint deduplication)
3. **Resume & Job Matching Engine** (Phase 2 - Semantic embeddings, Skill extraction, Rule filtering)
4. **Telegram Daily Job Digest** (Phase 3 - Threshold filtering, Notification deduplication, Telegram delivery)
5. **Scheduler & Reliability Infrastructure** (Phase 4 - APScheduler daemon, Heartbeat monitoring, Stale health alerts, Failure isolation)
6. **Multi-Source Yellow-Tier Expansion** (Phase 5 - Internshala HTML parsing, rate-limiting jitter, configurable intervals, per-source status tracking)
7. **Gmail API Alert Email Ingestion** (Phase 6 - Read-only OAuth 2.0 access, base64url MIME decoding, LinkedIn & Indeed HTML email parsing, deduplication)

## 2. Phase Scope & Architecture

### Phase 1: Ingestion & Deduplication (Adzuna)
- Fetches jobs via Adzuna API with search keywords.
- Normalizes titles, locations, descriptions, and salary currency.
- Generates SHA-256 content fingerprints for deduplication in SQLite (`data/jobs.db`).

### Phase 2: Resume & Job Matching Engine
- **Semantic Embeddings**: Uses `all-MiniLM-L6-v2` via `sentence-transformers` for cosine similarity calculation.
- **Skill Overlap**: Regex boundary matching against canonical tech skills.
- **Rule Filtering**: Evaluates experience level (filtering senior/lead roles) and location preferences.
- **Weighted Match Score (0 - 100)**: 50% Semantic + 30% Skill + 20% Rule compatibility.

### Phase 3: Telegram Daily Job Digest
- **Decoupled Notification Service**: `TelegramNotifier` handles HTTPS requests to the official Telegram Bot API (`sendMessage`).
- **Minimum Score Threshold**: Notifies only matches meeting or exceeding `TELEGRAM_MIN_MATCH_SCORE` (default 70.0).
- **Message Formatting & Chunking**: Formats clean job cards and chunks messages under character limits while strictly preserving job card boundaries.
- **Notification Deduplication & Failure Resilience**: Tracks sent notifications in SQLite (`job_notifications` table). Records notifications **only after** delivery confirmation.

### Phase 4: Scheduler, Reliability & Heartbeat Monitoring
- **APScheduler Daemon**: `PipelineScheduler` runs periodic monitoring cycles using background interval triggers.
- **Overlap & Misfire Protection**: Configured with `max_instances=1`, `coalesce=True`, and `misfire_grace_time=900` to prevent duplicate concurrent runs.
- **Failure Isolation**: Component failures (Adzuna network errors, missing resume, or Telegram HTTP errors) are caught, logged, and isolated. No single error terminates the scheduler daemon process.
- **Pipeline Run Tracking**: Every execution is recorded in SQLite (`pipeline_runs` table) with status (`SUCCESS`, `PARTIAL_FAILURE`, `FAILED`), metrics, duration, and error details.
- **Heartbeat & Health Evaluation**:
  - `HEALTHY`: Last successful run completed within `HEARTBEAT_TIMEOUT_MINUTES`.
  - `STALE`: Time since last successful run exceeds `HEARTBEAT_TIMEOUT_MINUTES`.
  - `FAILED`: Last run suffered a critical failure.
- **Deduplicated Health Alerts**: Dispatches a Telegram operational alert upon transitioning into a `STALE` state, recorded in `health_alerts` to prevent notification spam. Automatically resolves active alerts when a run succeeds.
- **Graceful Shutdown**: Listens for `SIGINT` and `SIGTERM` signals to cleanly stop the scheduler daemon without interrupting active DB transactions.

### Phase 5: Internshala Yellow-Tier Source Integration
- **Source Abstraction**: Implements `InternshalaJobSource(BaseJobSource)` returning standard internal `Job` dataclass objects seamlessly into the existing pipeline.
- **HTML Ingestion**: Uses `requests` and `BeautifulSoup4` with fallback CSS selectors to parse publicly available job and internship listings.
- **Fresher & Internship Focus**: Preserves employment type metadata (Internship, Fresher Job, Job) without filtering at the fetcher level.
- **Rate-Limiting & Jitter**: Configurable delay jitter (`INTERNSHALA_REQUEST_DELAY_MIN` to `INTERNSHALA_REQUEST_DELAY_MAX`) between sequential page requests. Injectable `sleep_fn` prevents delay in unit tests.
- **Source-Level Failure Isolation**: If Internshala returns HTTP 403, 429, 503, or security challenges (e.g. Cloudflare), execution halts gracefully for Internshala while Adzuna, SQLite, matching, Telegram digest, scheduler, and heartbeat continue uninterrupted.
- **Configurable Intervals**: Runs on an independent configurable interval (`INTERNSHALA_INTERVAL_HOURS`, default 12 hours). The scheduler checks `source_runs` to determine if Internshala is due.
- **Cross-Source Fingerprint Deduplication**: Prevents duplicate Telegram notifications across sources when identical job postings appear on both Adzuna and Internshala.
- **Per-Source Health Metrics**: Tracks execution outcome in `source_runs` (`SUCCESS`, `PARTIAL_FAILURE`, `FAILED`, `BLOCKED`).

### Phase 6: Gmail API + LinkedIn & Indeed Alert Email Ingestion
- **Read-Only OAuth 2.0**: Uses `https://www.googleapis.com/auth/gmail.readonly`. Never modifies, deletes, moves, or marks emails as read.
- **No Web Scraping**: Ingests job-alert emails sent directly to Gmail by LinkedIn and Indeed.
- **HTML & MIME Decoding**: Decodes base64url encoded `text/plain` and `text/html` payloads using BeautifulSoup.
- **Isolated Email Parsers**:
  - `LinkedInEmailParser`: Extracts title, company, location, URL (`linkedin.com/jobs/view/...`), job ID (`li_<id>`), and description snippet.
  - `IndeedEmailParser`: Extracts title, company, location, canonical URL (`indeed.com/viewjob?jk=...`), job ID (`ind_<jk>`), and description snippet.
- **Deduplication**: Shares Level 1 `(source, source_job_id)` and Level 2 SHA-256 fingerprinting with the existing pipeline.
- **Failure Isolation**: One malformed email or Gmail API error is caught and logged as a partial/source failure without halting other sources or the scheduler.
- **Safe Manual Testing**: Includes `--gmail-test` CLI option for safe dry-run manual testing.

## 3. Configuration Parameters

Set environment variables in `.env`:

```env
# Phase 1: Adzuna API Credentials
ADZUNA_APP_ID=your_app_id_here
ADZUNA_APP_KEY=your_app_key_here
ADZUNA_COUNTRY=in
ADZUNA_RESULTS_PER_PAGE=20
ADZUNA_MAX_PAGES=2

# Phase 5: Internshala Yellow-Tier Configuration
INTERNSHALA_ENABLED=true
INTERNSHALA_INTERVAL_HOURS=12
INTERNSHALA_REQUEST_DELAY_MIN=2
INTERNSHALA_REQUEST_DELAY_MAX=5
INTERNSHALA_MAX_PAGES=3
INTERNSHALA_KEYWORDS="artificial intelligence, machine learning, data science, computer vision, deep learning, NLP, AI engineer, machine learning engineer, data scientist, Python"

# Phase 6: Gmail API Configuration (Disabled by default)
GMAIL_ENABLED=false
GMAIL_CREDENTIALS_PATH=credentials.json
GMAIL_TOKEN_PATH=token.json
GMAIL_QUERY_LIMIT=50
GMAIL_LOOKBACK_DAYS=2
GMAIL_LINKEDIN_QUERY="from:(linkedin.com) newer_than:2d"
GMAIL_INDEED_QUERY="from:(indeed.com) newer_than:2d"

# Database & Resume Settings
DB_PATH=data/jobs.db
RESUME_PATH=data/resume/base_resume.txt
EMBEDDING_MODEL=all-MiniLM-L6-v2

# Phase 2: Matching Weights (Must sum to 1.0)
SEMANTIC_WEIGHT=0.50
SKILL_WEIGHT=0.30
RULE_WEIGHT=0.20
MIN_MATCH_SCORE=60.0

# Phase 3: Telegram Bot Credentials
TELEGRAM_BOT_TOKEN=123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ
TELEGRAM_CHAT_ID=987654321
TELEGRAM_MIN_MATCH_SCORE=70.0
TELEGRAM_MAX_JOBS_PER_DIGEST=10
TELEGRAM_ENABLED=true
SEND_EMPTY_DIGEST=false

# Phase 4: Scheduler & Heartbeat
SCHEDULER_ENABLED=true
SCHEDULER_INTERVAL_MINUTES=60
HEARTBEAT_TIMEOUT_MINUTES=180
RUN_ON_STARTUP=true
```

## 4. Running the Application

### Scheduled Monitoring Daemon (Phase 4, 5 & 6 Scheduler Mode)
Runs APScheduler as a long-running background service daemon:
```bash
python3 -m app.main --scheduler
```

### Single Execution Run (Manual / Cron Mode)
Executes one complete monitoring pipeline cycle (Ingestion -> Matching -> Digest -> Health check) and exits:
```bash
python3 -m app.main --run-once
```

### Phase 6 Gmail API Ingestion Dry-Run
Executes a safe manual dry-run of LinkedIn and Indeed Gmail alert email ingestion without modifying emails or sending Telegram notifications:
```bash
python3 -m app.main --gmail-test
```
