# AI Job-Matching & Monitoring Agent (Phase 1 & Phase 2)

A reliable, modular job ingestion, deduplication, and resume-to-job matching pipeline designed for a B.Tech Artificial Intelligence & Data Science student in India seeking relevant AI, Machine Learning, Data Science, and Python Developer positions.

> **Disclaimer**: The match score generated by this system is a **ranking signal**, NOT a probability of hiring or interview success.

---

## 1. Project Purpose & System Pipeline

The long-term pipeline of the AI Job-Matching & Monitoring Agent encompasses:
1. **Source Fetchers** (Phase 1 - Adzuna API)
2. **Dedup & SQLite Storage** (Phase 1 - Exact & Fingerprint deduplication)
3. **Resume & Job Matching Engine** (Phase 2 - Semantic embeddings, Skill extraction, Rule filtering)
4. **Resume Tailoring & Notifications** (Future Phases)

Phase 1 & Phase 2 provide a complete, offline-capable ingestion, normalization, embedding, matching, and ranking engine.

---

## 2. Phase 2 Scope & Matching Methodology

### 1. Resume Loading
- Reads and normalizes candidate base resume from `data/resume/base_resume.txt`.
- Normalizes whitespace and extracts canonical skills.

### 2. Semantic Embeddings (`sentence-transformers`)
- Uses a local, lightweight model (`all-MiniLM-L6-v2`).
- Pre-computes resume embedding vector once.
- Constructs deterministic job representations (`{title}. Category: {category}. Company: {company}. Location: {location}. {description}`).
- Computes cosine similarity between resume and job vectors.

> **Why Cosine Similarity Alone is Insufficient**: High semantic text similarity (e.g. 0.85) between a resume and a job description does not account for hard constraints like required years of experience, specific mandatory technical skills, or geographic preferences. A 10+ year Senior Lead role description will sound semantically similar to an AI resume, but is incompatible for an entry-level candidate.

### 3. Skill Extraction & Overlap
- Deterministic, boundary-aware regex matching (no LLMs needed).
- Canonical skill mapping (e.g. `sklearn`, `scikit learn`, `scikit-learn` -> `Scikit-learn`).
- Calculates matched skills, missing skills, and skill overlap ratio.

### 4. Rule-Based Experience & Location Filtering
- **Experience Rule**:
  - `MATCH`: Entry-level, intern, fresher, graduate, junior, 0-1 years.
  - `MISMATCH`: Senior, lead, principal, manager, architect, 5+ years.
  - Hard Filter (`FILTERED` status): Obvious seniority mismatch sets status to `FILTERED` with explicit reason.
- **Location Rule**:
  - Evaluates location against preferred cities (`Bengaluru`, `Chennai`, `Remote`, `India`, etc.).

### 5. Transparent Composite Score (0.0 to 100.0)
Weighted composite match score:
- **Semantic Similarity**: 50%
- **Skill Overlap**: 30%
- **Rule Compatibility**: 20%

Status assignment:
- `FILTERED`: Senior/experience incompatibility.
- `MATCH`: Final Score >= `MIN_MATCH_SCORE` (default 60.0).
- `PARTIAL_MATCH`: Final Score < `MIN_MATCH_SCORE`.

## 4. Setup & Configuration (.env)

Edit `.env` or set environment variables:

```ini
ADZUNA_APP_ID=your_app_id
ADZUNA_APP_KEY=your_app_key
ADZUNA_COUNTRY=in
ADZUNA_RESULTS_PER_PAGE=20
ADZUNA_MAX_PAGES=2

RESUME_PATH=data/resume/base_resume.txt
EMBEDDING_MODEL=all-MiniLM-L6-v2

SEMANTIC_WEIGHT=0.50
SKILL_WEIGHT=0.30
RULE_WEIGHT=0.20

MIN_MATCH_SCORE=60
PREFERRED_LOCATIONS=Coimbatore,Chennai,Bangalore,Bengaluru,Hyderabad,Pune,Remote,India
```

> **Note**: `SEMANTIC_WEIGHT + SKILL_WEIGHT + RULE_WEIGHT` must sum to 1.0.
